2 · Life of one reading

Follow a single power measurement from the plug to the screen.

Poll

Every POLL_INTERVAL = 60 s the collector calls each Shelly over the LAN (GET http://<ip>/rpc/Switch.GetStatus?id=0, 5 s timeout) and reads current, voltage, apower. All 8 devices are queried concurrently with asyncio.gather.

Derive & store locally

energy_minute_wh = power_w / 60. The row is committed to local PostgreSQL (energy_minute). Each device accumulates a buffer; after 60 minutes an energy_hourly row (averages + total Wh) and a weather_hourly row (Open-Meteo, HTTPS) are written.

Publish to local MQTT

Each metric becomes a small JSON message {timestamp, valeur, unite, capteur_id}, published QoS 1 over MQTT 5 on the local Mosquitto: minute data → telemetrie, hourly energy & weather condition → comptes-rendus, heartbeat every 60 s → etat.

Agent: aggregate, buffer, sign

h2s_agent subscribes to the local topics, persists records in its buffer (up to 7 days offline), wraps the payload in an envelope and signs the canonical string with its Ed25519 key (ECDSA-P256 if held in the TPM).

Send over TLS 1.3

The agent opens an outbound MQTT/TLS 1.3 session to EMQX (:8883) with its uuid account and publishes to h2s/agents/<uuid>/telemetrie|comptes-rendus|etat. If the link is down, data stays in the buffer and is replayed on reconnect.

Broker authorisation

EMQX ACL (deny-by-default) lets an agent publish only to its own three topics and subscribe only to its own ordres. Wildcards, $SYS and other agents' subtrees are refused.

Cloud verification

agent-sync (QoS 1 subscriber) checks: timestamp within ±5 min, agent known & not revoked, signature valid against the enrolled public key, nonce never seen (edge_nonces), topic belongs to the agent, size ≤ 256 KB, ≤ 5 000 msg/h. Unsigned raw JSON is dropped.

Persist

Valid readings land in PostgreSQL (edge_raw_readings); message_id ensures idempotence on QoS 1 duplicates. Other services (digital twin, reporting, prediction) consume them via the gateway / outbox.

Predict

The AI engine builds hourly features (lags, calendar, weather) and returns 1 h and 24 h forecasts for production, consumption, weather and price, each with a confidence score and peak flag.

Display & act

The dashboard (OIDC-protected REST) shows live and forecast curves. Decisions (e.g. charge/discharge) come back as cloud-signed messages on ordres; the agent verifies signature, target site, validity and rules before executing — idempotently.

🔑 Enrollment

Platform super-admin creates the site and a one-time code → on the box h2s_agent enroll generates its own agent UUID and Ed25519 key → public key stored in edge_clients → DevOps adds the matching MQTT account. Revocation = remove account + revoke client.

⏱ Clock discipline

Because of the ±5 min window, the Pi needs reliable NTP (chrony). The agent also re-syncs from the server time returned on responses and on 401 headers.

🔁 Replay & idempotence

Unique nonce (purged hourly), message_id and sequence. QoS 1 duplicates and re-sent orders are executed only once (decision_id cache).

5 · Prediction models

Package Modele_AI/h2s_forecast (v2.0.0). Trained offline on historical data, models stored as trained_models/<name>.pkl with metrics in metrics.json.

Inputs

  • Shelly minute data (4 CSV exports) → hourly consumption
  • Open-Meteo ERA5 observations + archived NWP forecasts (lead day 0 / 1)
  • EPEX day-ahead price, zone FR (hourly, 15-min averaged)
  • Site: 48.90 N / 2.35 E; simulated PV 200 W, wind 200 W, battery 2.2 kWh

Features & training

  • Lags, moving averages, sine/cosine calendar, forecast-vs-observed gap
  • Masked-input augmentation so trees learn a "missing input" branch
  • Chronological splits with a purge gap (no leakage)
  • Optuna TPE (30 trials) + early stopping (100 rounds), 5-fold TimeSeriesSplit

Outputs

  • Forecast per horizon + confidence % (High ≥ 85, Medium ≥ 70, else Low)
  • Peak flag: above P90 of training distribution
  • Feature importance and report figures

6 · Protocols & topic reference

The four MQTT topics (QoS 1, retain=false, persistent session, no last-will).

TopicDirectionContent
h2s/agents/<uuid>/telemetriePi → cloudlive (~5 s site snapshot) · raw readings: power, current, voltage, energy/min, weather metrics
h2s/agents/<uuid>/comptes-rendusPi → cloudrecords (hourly energy aggregates, weather condition) · command_result
h2s/agents/<uuid>/etatPi → cloudstate: version, buffer size, clock sync, TPM probe — every 60 s
h2s/agents/<uuid>/ordrescloud → Pidecision · command, signed by cloud, subscribe-only

Sensor fields

  • Shelly: current_a, voltage_v, power_w, energy_minute_wh, total_energy_wh
  • Weather: temperature, humidity, wind_speed, precipitation, ghi, condition

Protocol stack

  • MQTT 5 (paho on Pi, Vert.x in Java, EMQX / Mosquitto brokers)
  • HTTP/HTTPS REST + JSON (Shelly, Open-Meteo, agent API, gateway, IOTA service)
  • Flower (gRPC) for federated learning (planned)
  • SQL (asyncpg / JDBC), SMTP/587 for alerts, Prometheus h2s_mqtt_* metrics

Deployment

  • Pi: Docker Compose (postgres + collector) / systemd h2s-agent.service
  • CI: GitHub Actions (flake8) on main
  • Cloud: VPS with Docker Compose (EMQX, agent-sync…), Ansible role mqtt in prod

7 · Honest status, gaps & inconsistencies

Spotted while reading the repository — worth resolving before production.

#FindingImpact
1Two edge code paths. H2S_Shelly_RPi collector publishes plain JSON; the cloud only accepts signed envelopes, so h2s_agent must sit in between (as documented). The collector's default broker is localhost:1883 without TLS.OK on loopback; must never point directly at EMQX.
2Encryption claim mismatch. README mentions AES-256-GCM payload encryption and ECDSA-SHA256 in a TPM; the onboarding docs and agent code describe TLS 1.3 + Ed25519 signatures (software key for now). No AES-GCM code was found.Payload is protected in transit by TLS, signed for integrity, but not separately encrypted end-to-end.
3TPM not yet active. key_store: software is the current recommendation; TPM via tpm2-pytss later.Key theft on a compromised Pi is possible.
4Mosquitto TLS version example still says tlsv1.2; spec requires 1.3.Align config.
5Orders handler is a TODO in main_collector.py (_handle_ordre).Cloud → Pi control loop not complete in the collector.
6Federated learning is a stub; models are currently trained centrally on CSV exports.No on-device model improvement yet.
7Dashboard front-end is not in this repository. It belongs to the Java platform (apps/projeth, apps/website); shown here from the backend study.Diagram block is inferred, not verified in code.
8IOTA: Devnet only, no auth, no funded wallet, not yet called by the Java backend; ledger anchoring defaults to the local PostgreSQL hash-chain.Blockchain proof is a proof-of-concept.
9Credentials in committed .env/defaults (h2s_pass, secret) and a Postgres port 5432 published by compose.Rotate and restrict before deployment.
